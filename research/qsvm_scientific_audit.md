## Original material finding (resolved): PSD-labelled exports contained raw matrices

At the reviewed revision, `experiment.py` calls `fit_kernel(train, cross, ..., repair=True)`, but `fit_kernel` replaces only its local variables with `psd_extension` outputs. The caller subsequently exports and diagnoses the original matrices under `noisy_PSD`, `noise_expectation_PSD`, and `readout-mitigated_PSD` names. Thus classification uses a corrected kernel while PSD-labelled saved matrices and diagnostics describe a different kernel. The raw and noisy-PSD saved arrays are identical, and a PSD-labelled diagnostic may still show negative eigenvalues.

Action: expose the actual training and cross matrices used by the classifier, or explicitly call `psd_extension` once in the caller and fit/export/diagnose those outputs. Preserve separately named raw matrices and raw diagnostics. Ensure the report's raw expected-noise RMSE comes from an explicitly raw expected matrix if that is the intended quantity. This is an artifact provenance bug, not a flaw in the correction mathematics. Scikit-learn consumes the supplied Gram matrices directly, so the exported matrix must match the one passed to training/prediction. [SVC documentation](https://scikit-learn.org/stable/modules/generated/sklearn.svm.SVC.html)

## Mathematical checks that passed source review

- Feature preparation has four qubits and two independent parameters repeated across them. Its data-dependent RZZ gates do not merely append a fixed entangler that cancels from the fidelity. `left.compose(right.inverse())` correctly implements U(right)-inverse after U(left); the ideal global all-zero probability is the specified squared overlap. [ComputeUncompute definition](https://qiskit-community.github.io/qiskit-machine-learning/stubs/qiskit_machine_learning.state_fidelities.ComputeUncompute.html)
- Exact kernel multiplication computes the squared complex inner product with correctly shaped train/train and test/train matrices. [SVC matrix shapes](https://scikit-learn.org/stable/modules/generated/sklearn.svm.SVC.html)
- `psd_extension` is mathematically consistent. If A has retained positive eigenpairs V,L, training features V sqrt(L) reproduce V L V-transpose. Test features B V L^(-1/2) yield cross kernel B V V-transpose against training features. A joint Gram matrix completed using these features is PSD. No test labels enter this operation. The threshold discards tiny positive values as well as negative ones, so describe this as truncation into the positive training eigenspace rather than an unqualified exact nearest-PSD projection. This conclusion is direct linear algebra.
- Quantum CV fits scaling only on each fold's training indices and applies it to validation points. Classical baselines use a preprocessing pipeline inside GridSearchCV. No preprocessing or primary hyperparameter-selection leakage was found. The winning CV score is a selection score, not an unbiased external performance estimate; the separate holdout supplies the latter. [scikit-learn leakage guidance](https://scikit-learn.org/stable/common_pitfalls.html)

## Noisy probabilities and readout: correct under the present assumptions

The circuit snapshots outcome probabilities before the final measurement; the four measured physical qubits are obtained from the compiled measurement map. Noise in preceding native gates affects that snapshot. Classical readout error is applied only when measurement counts are generated. Applying the classical channel to the saved pre-readout probabilities therefore does not double count readout. Aer supports saving probabilities on a chosen qubit subset. [save_probabilities API](https://qiskit.github.io/qiskit-aer/stubs/qiskit_aer.library.save_probabilities.html)

The synthetic readout matrix is a tensor product of four identical symmetric independent bit-flip matrices. It is symmetric, so `pre_readout @ channel.T` and inversion with the transpose are correct here. Aer defines ReadoutError rows by true outcome and columns by recorded outcome. If future noise becomes asymmetric, qubit-dependent, or correlated, the current transpose and tensor-order conventions must be revisited explicitly rather than copied unchanged. Inverting this known channel is an ideal-calibration ablation, not hardware calibration. Clipping mitigated all-zero estimates introduces bias; preserving unclipped estimates is appropriate. [ReadoutError API](https://qiskit.github.io/qiskit-aer/stubs/qiskit_aer.noise.ReadoutError.html)

The depolarizing parameter is the coefficient in E(rho)=(1-lambda)rho+lambda I/d. It is not numerically equal to an average gate infidelity. The generated report correctly states this distinction. Applying the one-qubit channel to RZ as well as SX/X is a disclosed synthetic convention; the result should not be interpreted as calibrated IBM hardware performance. [depolarizing_error API](https://qiskit.github.io/qiskit-aer/stubs/qiskit_aer.noise.depolarizing_error.html)

## Accounting and interpretation cautions

1. The primary workload is correctly 4,840 pairs including 80 measured diagonal diagnostics, rather than the 4,760 minimum excluding known ideal diagonals. Compile-before-bind gives one structural count for every pair. Parameter-bound recompilation might remove more diagonal gates, so the measured workload is a specified policy rather than a lower bound.
2. Capturing SWAPs immediately after SabreSwap is appropriate; final native CX count includes routing decomposition and later cancellation. Do not equate `3*SWAPs` with net CX overhead. SABRE is a heuristic, and the graph-distance placement objective is not proof of minimum compiled cost. Existing prose discloses this. [SabreSwap API](https://quantum.cloud.ibm.com/docs/en/api/qiskit/qiskit.transpiler.passes.SabreSwap)
3. The training triangle is mirrored by construction. `symmetry_error=0` therefore checks assembly, not whether the noisy device physically produces identical values for both ordered circuits. If making an experimental symmetry claim, measure a small reverse-pair diagnostic separately; otherwise state that symmetry is enforced by mirroring. This is a direct inference from `assemble`.
4. The readout/gate-noise expectation resampling is a valid Bernoulli Monte Carlo sensitivity study. It does not represent fresh hardware runs, drift, recalibration, or dataset/split uncertainty. The generated report already distinguishes these. Matching seeds across A/B pairs trials but does not turn simulator time into quantum device time.
5. The selected ring circuit tests whether a physical four-cycle reduces routing relative to a chain. A/B cost conclusions are conditional on this feature map, placement, transpiler and synthetic gate model. Extra qubits alone are not the causal explanation. Keep architecture controls and avoid a universal architecture ranking or quantum-advantage claim.
6. Resolved cache issue: the original cache key omitted the actual `pairs` sequence, risking incorrect reuse after schedule changes. The final code includes `pair_schedule_sha256` computed from the full ordered integer pair array.
